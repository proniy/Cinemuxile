Цель работы

Освоить организацию совместной работы над проектом с использованием системы контроля версий, структурировать репозиторий и определить порядок фиксации вклада участников.

1. Назначение проекта

Команда «Ни шагу вперед» рассматривает проект «Сервис рекомендаций фильмов». Сервис предназначен для упрощения выбора фильма за счёт поиска, фильтров и рекомендаций по предпочтениям пользователя.

Адрес репозитория, GitHub-логины и сведения об истории изменений должны быть добавлены после проверки реального проекта.

2. Структура репозитория

Рекомендуемая структура по методичке: README.md; docs/team-contract.md; docs/roles-and-responsibilities.md; docs/raci-matrix.md; каталог practical-works с папками practical-work-01 … practical-work-08; в каждой работе — report.md и assets/, а при необходимости src/; в корне также scripts/ и .gitignore.

Для самостоятельной работы № 2 материалы размещаются в practical-works/practical-work-02/report.md и practical-works/practical-work-02/assets/.

3. Порядок командной работы

Каждый участник работает под своей учётной записью. Для отдельной задачи создаётся ветка, изменения фиксируются осмысленным коммитом, после чего ветка отправляется в удалённый репозиторий. Для проверки изменений используется Pull Request и ревью другим участником.

Пример сообщения коммита: «docs: добавлено описание целевой аудитории». Это пример, а не утверждение о существующем коммите.

6. Контрольные вопросы

1. Репозиторий хранит файлы проекта и историю изменений.

2. Git помогает работать параллельно, отслеживать изменения и возвращаться к предыдущим версиям.

3. Коммит — зафиксированный набор изменений; сообщение должно быть коротким и содержательным.

4. Ветка — отдельная линия разработки; main обычно содержит согласованную версию.

5. Pull Request — запрос на включение изменений в другую ветку с возможностью обсуждения и ревью.

6. История коммитов показывает авторов, время и содержание изменений.

7. Учётные записи позволяют идентифицировать участников и управлять доступом.

7. Вывод
