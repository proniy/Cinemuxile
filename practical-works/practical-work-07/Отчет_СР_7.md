Цель работы

Проверить прототип по функциональным требованиям и сценариям, зафиксировать обнаруженные проблемы и определить необходимые доработки.

1. Подход к проверке

Проверка проводится по сценариям. Для каждого фиксируются начальные условия, действия, ожидаемый результат и фактический результат. Нельзя отмечать тест успешно пройденным до его реального выполнения.

2. План тестирования

T-01: поиск существующего названия — должен появиться соответствующий фильм.

T-02: поиск без совпадений — должно появиться сообщение об отсутствии результатов.

T-03: фильтр по жанру — должны остаться фильмы выбранного жанра.

T-04: открытие карточки — должны отображаться подробности и возврат к списку.

T-05: подбор рекомендаций — должен появиться список по выбранным параметрам.

T-06: навигация — переходы между главной, каталогом и карточкой должны работать.

3. Таблица результатов

| ID | Проверка | Ожидаемый результат | Фактический результат / статус |
| --- | --- | --- | --- |
| T-01 | Поиск существующего названия | Показан подходящий фильм | Заполнить после проверки |
| T-02 | Поиск без совпадений | Сообщение об отсутствии результатов | Заполнить после проверки |
| T-03 | Фильтр по жанру | Остались фильмы выбранного жанра | Заполнить после проверки |
| T-04 | Открытие карточки | Показаны подробности и возврат | Заполнить после проверки |
| T-05 | Подбор рекомендаций | Список по выбранным параметрам | Заполнить после проверки |
| T-06 | Переходы между экранами | Нет неверных переходов | Заполнить после проверки |

После проверки заполнить фактический результат, статус «пройден/не пройден», описание дефекта и ссылку на скриншот. До проверки оставить статус «не проверено».

4. Возможные области проверки

Проверить, обновляет ли фильтр список; обрабатывается ли пустой поисковый запрос; корректно ли открывается карточка; не перекрываются ли элементы на узком экране; есть ли сообщение при пустом результате. Это направления проверки, а не утверждение о найденных ошибках.

5. Порядок доработки

Для каждого дефекта записать шаги воспроизведения, ожидаемое и фактическое поведение, приоритет и предполагаемое исправление. После исправления повторить соответствующий тест и сохранить подтверждающий скриншот.

6. Контрольные вопросы

1. Проверка сопоставляет фактическое поведение с требованиями.

2. Тестовый сценарий содержит условия, шаги и ожидаемый результат.

3. Дефект — воспроизводимое отклонение от ожидаемого поведения.

4. Приоритет определяется влиянием на основные задачи и серьёзностью проблемы.

5. Повторное тестирование подтверждает исправление и помогает обнаружить побочные эффекты.

7. Вывод

Подготовлен план проверки прототипа. Итоговый вывод о качестве возможен после выполнения тестов; реальные результаты и скриншоты нужно внести в отчёт и папку assets.

Примечание по заполнению отчёта

Места, где требуются фактические ссылки, скриншоты, результаты командной работы или подтверждение выполнения, нужно заполнить после получения соответствующих материалов. В документ не внесены вымышленные адреса репозитория, коммиты, результаты тестирования и изображения.
